## B. 公式枚举 vs 神经路由 — 关键审计结论

### B.1 代码路径追踪

**Smoke test** (`scripts/train_static_router_smoke.py`):
1. 第149行: `router = StaticFormulaRouter(...)` — 实例化神经路由器
2. 第494行: `r_out = router(data.attrs)` — 属性输入路由器,产生logits
3. 第507-527行: **公式枚举** — 对每个候选公式单独模拟,计算 train-set MSE
4. 第530行: `best = combo_losses.argmin(dim=-1)` — 找到每basin MSE最低的公式
5. 第531行: `F.cross_entropy(logits, best)` — 路由器学习预测枚举标签
6. 第576行: `r_out["selected"] = logits.argmax(dim=-1)` — 最终选择来自路由器logits

**Calibrated pilot** (`scripts/train_static_router_camels_calibrated_pilot.py`):
1. 第461行: `router = StaticFormulaRouter(...)` — 实例化神经路由器
2. 第490行: `r_out = router(data.attrs)` — 属性输入
3. 第507-527行: **公式枚举** — 枚举所有候选,计算MSE
4. 第530-531行: cross-entropy训练
5. 第592-600行: `rf_out = router(data.attrs)`, 选择来自 `rf_out["selected"]`

**CAMELS pilot** (原始版 `scripts/train_static_router_camels_pilot.py`):
1. 第278行: `router_model = HbvStaticFormulaRouter(...)` — 集成版神经网络路由器
2. 第303行: `out_dict = router_model(forcing_t, attr_t, normalized)` — 属性输入
3. 第311行: `loss_q = F.mse_loss(Qsim_cut, targ_cut)` — **MSE loss, 但梯度不流经router**
4. 第321-324行: 仅entropy/default penalties作用于router

### B.2 判定矩阵

```text
Formula enumeration diagnostic:            YES (用作训练监督信号)
Neural StaticFormulaRouter training:       YES (StaticFormulaRouter参数被梯度更新)
Static attributes used by router:          YES (data.attrs → router → logits)
Selection generated by router logits:      YES (argmax over router logits)
Selection generated by posterior metric search:  PARTIALLY (训练标签来自枚举MSE,但最终选择是logits argmax)

关键区分:
- 训练阶段: 公式枚举为路由器提供 supervised labels
- 推理/评估阶段: 选择来自 router.forward(attrs) 的 argmax(logits)
- 没有使用 eval-NSE 反向选择公式 (eval期间只跑一次router.forward)
```

### B.3 泄漏风险评估

| 泄漏路径 | 风险 | 说明 |
|----------|------|------|
| 训练标签生成使用训练期数据 | MEDIUM | 枚举的MSE标签来自训练期 — 这是标准的supervised learning,不是data leakage |
| 评估指标反选公式 | LOW | 最终评估使用router.forward,未在eval集上枚举选择 |
| 路由器不学习(梯度为0)的风险(CAMELS pilot原版) | HIGH | 原始policy-gradient的路由器梯度可能很弱 |

### B.4 最终判定

```text
Static router learning: PARTIAL (训练机制works, 但需要清理训练/评估分离)
Ready for expanded experiment: NO (见下方原因)
```

**理由**: 虽然神经网络路由器确实在工作并学习,但存在以下需要先解决的问题:

1. **训练-评估共享数据**: 当前校准pilot中,公式枚举使用同一时间窗口的数据生成标签训练路由器,然后用同一窗口评估。训练期和验证期未分离。
2. **单basin证据不足**: 仅1个basin显示R4选择改善,需要多basin复现。
3. **CAMELS pilot原始版路由学习不充分**: 使用policy-gradient,但Qsim→router的梯度路径不存在。
